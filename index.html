查表生成器

x64 系统调用表 → shellcraft.amd64.linux.syscall(...)。顺序固定：rax=NR, rdi, rsi, rdx, r10, r8, r9（第 4 个参数是 r10，不是 rcx）。

这是干什么的

写 PWN 的 exp 时，查系统调用号、记参数顺序、记每个参数走哪个寄存器、拼 shellcraft 调用链、拼 ROP 链，都要翻 man、翻表、翻笔记。这个页面把这些事收到一处：选架构 → 搜调用 → 按提示填参数 → 生成能粘进 exp 的 pwntools 代码骨架，填实参数、回 VM 对真题跑通才算数，seccomp 白名单检查和 ROP 链模板也在同一页。

已按 x86-64 调用号表（syscall_64.tbl）复核：205 set_thread_area、211 get_thread_area、212 lookup_dcookie 在 amd64 上没有实现，调用只会返回 -ENOSYS，已从表中去掉（i386 上 205/211/212 是 getgroups32/getresgid32/chown32 等真实调用，243/244 才是 set/get_thread_area，不受影响）。没收录的号分两类：①未分配空号只有 337–423（共 87 个）；②有名无实现、调用只会返回 -ENOSYS 的 17 个：134 uselib、156 _sysctl、174 create_module、177 get_kernel_syms、178 query_module、180 nfsservctl、181 getpmsg、182 putpmsg、183 afs_syscall、184 tuxcall、185 security、205 set_thread_area、211 get_thread_area、212 lookup_dcookie、214 epoll_ctl_old、215 epoll_wait_old、236 vserver。注意 175=init_module、176=delete_module、179=quotactl 是真实可用的调用，335=uretprobe、336=uprobe 也是真实存在的新调用，都不是空号。找不到就换英文名再试。

地址从哪来：gadget 用 ROPgadget --binary ./prog | grep "pop eax" 或 ropper 找；offset 用 cyclic 试出来；BSS 看 readelf -S ./prog 的 .bss（要可写、够放 8 字节）。

    
没有 pop3 只有单个 pop 的回退：别硬套模板，拆成单个 pop 逐个设寄存器。i386 read(0, bss, len)：pop eax;ret→3、pop ebx;ret→0、pop ecx;ret→bss、pop edx;ret→len，再 int 0x80；execve(bss, 0, 0)：pop eax;ret→11、pop ebx;ret→bss、pop ecx;ret→0、pop edx;ret→0，再 int 0x80。amd64 read(0, bss, len)：pop rax;ret→0、pop rdi;ret→0、pop rsi;ret→bss、pop rdx;ret→len，再 syscall；execve(bss, 0, 0)：pop rax;ret→59、pop rdi;ret→bss、pop rsi;ret→0、pop rdx;ret→0，再 syscall。单个 pop gadget 用 ROPgadget 按寄存器名分别找：ROPgadget --binary ./prog | grep "pop rax"、ROPgadget --binary ./prog | grep "pop rdi"、ROPgadget --binary ./prog | grep "pop rsi"、ROPgadget --binary ./prog | grep "pop rdx"。

填法口诀：调用名看 NAME，顺序看 ARG0→ARG5，值按参数类型分四类——①字符串指针（文件名/路径）：先 pushstr 再传 'rsp'，本页已自动带上；②长度/数量（count/len）：才是自己按数据大小定，给 0x100/0x1000；③权限/标志位（mode/prot/flags）：mode 用八进制 0o777/0o755/0o644，prot/flags 用下方速查的常量值相加；④fd/地址/偏移：fd 是 0/1/2 或上一步 open 返回的 rax，地址是 mmap 返回的 rax 或 'rsp'，偏移一般填 0。
